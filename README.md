# ld_skill

> 把 LD 老师的论文写作方法，蒸馏成随时可以调用的写作判断。

一段话可能语法正确、引文也齐全，读起来却还是让人想问：“所以呢？”有时是文献没有为后面的预测铺好前提，有时是两个变量之间少了一步解释，也有时是把“开始思考”直接写成了“得出某种结论”。`ld_skill` 关注的正是这些容易藏在流畅句子里的问题。

**名字从哪里来？** `ld` 来自我一位名叫 LD 的老师。我把从 LD 老师的写作指导中学到的方法，结合对管理学实证论文写法的整理，做成了这个可重复使用的 Skill。这里的“蒸馏”不是模仿某位老师的口头禅或固定句式，而是尽量留下改稿时有用的判断：读者还缺什么前提？这一句究竟解释了哪一步？当前证据允许写到哪里？

[查看 Skill 入口](skills/ld-skill/SKILL.md) · [详细使用说明](skills/ld-skill/README.zh-CN.md) · [文献综述与假设推导指南](skills/ld-skill/references/09-literature-and-hypothesis-development.md)

## 它怎样帮你改稿

`ld_skill` 面向**中英文管理学实证论文**。你给出原文、批注、相关文献或研究结果，并说明想处理哪一部分，它会按该部分的论证任务写作，而不是给全文套同一种模板。

| 你正在写 | 它会重点看什么 |
| --- | --- |
| 标题、摘要、引言 | 研究问题是否具体，读者能否看懂为什么需要这个研究；摘要是否准确概括结果与边界 |
| 文献综述、理论、假设 | 文献为哪一步提供前提；相邻关系为何成立；比较条件、机制与假设是否一一对应 |
| 研究设计与方法 | 各研究的分工、程序、测量和样本信息是否清楚，避免把方法写成操作流水账 |
| 结果与统计呈现 | 数值、方向、显著性与文字结论是否一致，不把不显著写成“没有效应” |
| 讨论、贡献、局限 | 回答原来的问题，说明真正新增的认识，同时守住证据范围 |
| 中文与英文修订 | 保持同一命题和证据强度，让两种语言各自自然，而非逐句直译 |

### 一个小例子：把“因此”前面的路走完

下面是**虚构的写法示例，不是可引用的研究发现**。给定材料只有两项：明确的申诉规则让申请人知道要提交哪些材料；准备成本包括辨认所需材料的工作量。

> **跳步：** 规则透明很重要，因此能够降低申诉准备成本。
>
> **补上连接：** 明确的规则使申请人知道哪些材料与申诉有关。他们不必逐项猜测提交要求，辨认所需材料的工作量因而减少。基于这一过程，本文预期规则透明有助于降低申诉准备成本。

改动的重点不是多写两句，而是让“知道要求”如何影响“准备成本”变得可见。如果材料并不支持这一步，Skill 应指出缺口，而不是补造一个看似合理的机制。理论推导还会检查另一个常见问题：**某件事使人开始思考，并不自动决定他最后会得出什么判断。**

## 怎样提出请求

不需要学习内部命令。在已安装的项目中选择 `ld_skill`，或显式写 `$ld-skill`，再用自然语言说明任务。尽可能附上待修改段落、相关批注、引言或前后文、已有文献、对应结果，以及希望保留的格式或篇幅。

**修改假设推导：**

> 请使用 $ld-skill，结合我的批注、引言和研究结果重写这部分假设推导。检查文献如何铺垫前提、每一步关系为何成立，以及调节条件下两组的比较方向。保留构念、假设方向和证据强度；涉及跨段调整时先提出具体方案。

**润色一段文字：**

> 请使用 $ld-skill 润色以下英文段落。优先修复读者难以理解的连接，保持引用与研究事实不变，按原段落结构交付可直接替换的正文。

**整理结果写法：**

> 请使用 $ld-skill 根据我给出的统计结果修改结果段。逐项核对数值、比较方向与文字结论；没有报告的分析不要补写。

它也能根据写作任务自动匹配；显式提及适合你希望确定使用这一套规则的时候。

## 改稿边界：你的研究，仍由你决定

在**原段落内部**，Skill 可以调整措辞、句序和衔接。若要移动、拆分、合并、增删段落，或把内容转移到另一段，它会先说明“原位置—拟调整—理由—影响”，等你同意具体方案后再改。[完整权限规则](skills/ld-skill/references/07-editing-permissions.md)

研究问题、构念、假设方向、数据、引文归属和证据强度也不能为了让文字更顺而悄悄改变。没有材料支持的前提会被标出来；已有文献的发现与本文提出的推论会分开表述。简短的方法或结果句已经清楚时，也不必因为使用了 Skill 就扩成理论段落。

## 安装与文件

仓库名称和界面显示名是 `ld_skill`；Skill 内部名称、目录及显式调用名分别是 `ld-skill`、`ld-skill/` 和 `$ld-skill`。

项目级使用时，把仓库中**整个** [`skills/ld-skill/`](skills/ld-skill/) 文件夹放到项目的 `.agents/skills/` 下。保留 `references/`、`assets/`、`tests/` 和 `agents/`；已有同名目录先备份。预期入口为：

```text
<项目目录>/.agents/skills/ld-skill/SKILL.md
```

安装后在该项目的新会话中调用一次，确认实际读取的是这一路径。项目级安装只覆盖相应本地项目；从 GitHub 更新仓库不会自动替换其他项目或电脑上的副本。[Codex 技能说明](https://developers.openai.com/codex/skills)

| 文件 | 用途 |
| --- | --- |
| [`SKILL.md`](skills/ld-skill/SKILL.md) | 任务入口、写作边界与按章节读取指南的路径 |
| [`references/01–08`](skills/ld-skill/references/) | 原有叙事、双语、方法、结果、讨论、来源、权限和交付检查指南 |
| [`references/09`](skills/ld-skill/references/09-literature-and-hypothesis-development.md) | 文献铺垫、机制连接、条件比较和假设递进的专项指南 |
| [`tests/`](skills/ld-skill/tests/) | 原有场景及新增的原创理论场景；场景文件本身不等于测试已通过 |
| [`assets/source-index.json`](skills/ld-skill/assets/source-index.json) | 公开书目信息与来源边界 |

仓库文件可在根目录运行 `shasum -a 256 -c checksums.sha256` 检查完整性。原始论文、私人精读记录及真实稿件测试材料不随公开仓库分发。来源与公开范围详见[来源说明](skills/ld-skill/references/06-exemplars-and-provenance.md)和[公开整理记录](PUBLICATION.md)；本仓库未添加开放许可证。

## 版本与验证

当前 `main` 已包含新版，当前电脑“学术科研”项目也已安装。一次本机新会话实际调用检查了中文与英文假设推导、方法段保持简洁、跨段修改先审批，以及所读取的技能路径。此前的新旧对照中，已测任务没有发现确认的硬性错误或实质退步；**尚未证明新版稳定优于旧版**，完整留出测试也未运行。文件完整性、一次调用成功与写作质量改善是不同的判断。

具体运行次数、比较结论及限制见[本轮验证记录](docs/updates/completion-validation-20260925.md)；较早一次候选的测试见[历史记录](docs/updates/hypothesis-development-validation.md)。这套方法用于帮助你写清论证，不替代文献核查、研究设计或统计判断。
